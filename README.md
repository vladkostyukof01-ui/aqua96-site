# Аква 96 — сайт поставщика оборудования для бассейнов и саун

Редизайн сайта aqua96.ru (Екатеринбург) на Node.js + Express + SQLite:
каталог направлений (бассейны/сауны/турецкие бани) с реальными подкатегориями
и брендами оборудования, список выполненных объектов, форма заявки и
админ-панель.

## Стек

- Express (сервер, роуты, API)
- better-sqlite3 (БД, режим WAL)
- express-session + bcryptjs (авторизация админа)
- express-rate-limit (защита от подбора пароля)
- helmet (security headers, CSP)

## Что нового относительно оригинала

Оригинал (aqua96.ru) на момент редизайна был недоступен — весь реальный
контент восстановлен из архива Wayback Machine (`_archive_raw/`): 26 реальных
товарных подразделов, список из 52 именных выполненных объектов, реальные
бренды оборудования, контакты и координаты. Добавлены форма заявки (у
оригинала её не было — только телефон/email) и админ-панель. Дизайн —
собственная концепция «профиль глубины» (палитра сэмплирована из логотипа
клиента), не повторяющая оригинальный шаблонный движок.

## Локальный запуск

```
npm install
npm run seed    # создаёт БД, наполняет реальными данными из архива, создаёт админа
npm start       # http://localhost:3502
```

Админ-панель: http://localhost:3502/admin — логин/пароль по умолчанию `admin` /
`aqua96-2026` (задаются через `.env`, обязательно смените перед реальным
использованием — скопируйте `.env.example` в `.env`).

## Перед деплоем — обязательно

1. Скопировать `.env.example` в `.env`, задать реальный `SESSION_SECRET`
   (длинная случайная строка) и свой `ADMIN_PASSWORD`.
2. Сменить пароль администратора через админ-панель, если уже был запуск с
   дефолтным паролем.
3. Заменить `ЗАМЕНИТЕ-НА-ДОМЕН.ru` на реальный домен во всех
   `<link rel="canonical">`, `robots.txt`, `sitemap.xml` (когда домен появится).
4. **Проверить реквизиты юрлица** в `public/privacy.html` — найден только ИНН
   (6658380000, из микроразметки архивной страницы контактов), полное
   юридическое наименование, ОГРН и КПП не были опубликованы на исходном
   сайте и не найдены в открытых источниках — заполните перед реальным
   использованием, если сервис работает от лица нового владельца.

## Деплой на PaaS (Render и подобные)

1. Создать новый Web Service, подключить репозиторий.
2. Build command: `npm install`
3. Start command: `npm run seed && npm start` (seed идемпотентен — безопасно
   запускать при каждом деплое, данные не задвоятся)
4. Задать переменные окружения (`SESSION_SECRET`, `ADMIN_USERNAME`,
   `ADMIN_PASSWORD`, `NODE_ENV=production`) в панели хостинга.
5. **Важно**: SQLite-файл должен жить на постоянном (не эфемерном) диске — на
   части бесплатных тарифов PaaS файловая система сбрасывается при каждом
   деплое.

## Деплой на VPS

1. Установить Node.js, склонировать репозиторий, `npm install`, `npm run seed`.
2. Установить PM2 (`npm install -g pm2`), запустить `pm2 start ecosystem.config.js`.
3. `pm2 save && pm2 startup` — чтобы сайт поднимался сам после перезагрузки сервера.
4. Настроить nginx как реверс-прокси на порт из `.env` (`PORT`), выпустить
   HTTPS-сертификат (Let's Encrypt/certbot).

## Резервное копирование

`npm run backup` — создаёт снапшот БД в `data/backups/` (хранит последние 14
копий). Поставьте эту команду в cron на хостинге (например, раз в сутки).

Восстановление: остановить сервер → удалить `*.db-wal`/`*.db-shm` → скопировать
нужный файл из `data/backups/` поверх `data/aqua96.db` → запустить сервер
заново.
